# 練習教材JSONの作り方

UTF-8のJSONファイルを作り、アプリの「自分のJSONを開く」で選ぶ。コメントや末尾の余分なカンマは使えない。参照用の完全な例はsamples/に4曲ある。ファイルは端末内で読むだけで送信しない。

## 拍は音符名ではなく、線とクリックの単位

1 beatは画面の通常拍線・クリック1個分。BPM80なら、この拍が1分に80個。四分音符や8分音符への換算は不要。beatはファイルの並び順ではなく、曲頭0からの絶対位置で指定する。途中の入力は0.5等にできる。

```json
{
  "schemaVersion":1,
  "id":"my-six-beats",
  "revision":"1",
  "title":"6拍の練習",
  "countInBeats":12,
  "events":[
    {"e":"tempo","beat":0,"bpm":100},
    {"e":"barline","beat":0,"style":0},
    {"e":"hint","beat":0,"text":"まずは左、次に右"},
    {"e":"note","beat":1,"key":"f"},
    {"e":"barline","beat":3,"style":1},
    {"e":"note","beat":4,"key":"j"},
    {"e":"barline","beat":6,"style":0},
    {"e":"hint","beat":6,"text":""}
  ]
}
```

## メタデータ

全項目必須。schemaVersionは1、id/revision/titleは空でない文字列。idは教材固有の名前、revisionは内容を変えたときに更新する版。記録はid・revision・速度ごとに分かれる。同じid/revisionのまま内容を変えると記録を共有するため、更新時は版を変える。

countInBeatsは曲頭0より前の予備拍数（0以上の整数）。4拍区切りの2小節なら8、6拍区切りの2小節なら12。アプリが小節数から予備拍を推測することはない。予備拍は初期BPMと選んだ速度で進み、準備入力は減点しない。ただし最初のノートの180ms前からは通常判定が有効。

アウフタクトも特別なイベントは不要。例えばcountInBeats=3、最初のノートbeat=0、次の小節頭のbarlineをbeat=1、その後5,9…と置けば1拍の入りを表せる。最初のノートをbeat=2など遅らせて、曲内に読む時間を作ってもよい。

## イベント

| e | 項目 | 意味 |
|---|---|---|
| tempo | beat, bpm | その拍から一定テンポ。beat=0に必ず1個置く |
| tempoRamp | beat, toBeat, toBpm | 終点へ拍線形に加速／減速。開始BPMは直前を継承 |
| barline | beat, style | 任意の区切り線。0は太い実線、1は別色の破線 |
| hint | beat, text | 次のhintまでことばを維持。空文字で消す。採点と無関係 |
| note | beat, key | 小文字a〜zの1文字。担当レーンへ自動配置 |

通常拍線・クリックは整数拍ごとに自動生成する。区切りは任意で、barlineなしも有効。途中3、次の大区切り6、次は11、あるいは3.5等も置ける。4/4や6/8、meterの指定は不要。barlineはテンポや採点を変えない。**初回のクリックは全て同じ短音・同じ強さ**とし、styleは視覚だけを変える。区切り位置に追加のクリックは鳴らさない。

hintはノートより先に置いて読む時間を作れる。同じ拍にhintが複数ある場合はファイル順で最後のものを使う。HTMLタグを入れても文字のまま表示する。

例：`{"e":"tempoRamp","beat":4,"toBeat":8,"toBpm":120}`。拍に対してBPMが直線で変化する。秒に対して直線ではない。終点後はそのBPMを維持する。ランプの重複やランプ途中のtempoは不可、終点ちょうどに次の制御は可能。同じ拍に複数のテンポ制御は不可。

## 対象キーと判定

| 指 | 左 | 右 |
|---|---|---|
| 小指 | Q A Z | P |
| 薬指 | W S X | O L |
| 中指 | E D C | I K |
| 人差し指・外側 | R F V | U J M |
| 人差し指・内側 | T G B | Y H N |

数字・記号・親指・同時ノート・長押しは初回対象外。JSONのkeyは小文字だが、実際のShift/CapsLockは問わない。日本語IMEはOFFで練習する。

画面では26文字を3段×10列の簡易キーボードに並べ、同じ列のキーを同じ指レーンへ対応させる。教材のnoteで使うキーが着色され、打鍵中は黄色に変わる。見せたいキーを増やすための追加JSON指定は不要。

±60/120/180msの3段階。実時間msの窓なので速度で幅は変わらない。同キーが近くても先の未判定ノートを優先する。360ms未満は警告するが読込可能。導入教材は読む時間と指を離す時間を十分確保する。

## 検証と将来の拡張

beat/toBeatは有限数、beatは0以上、toBeatは開始より後、BPMは20〜400。ノート1個以上、同拍のノートは1個だけ。ファイル5MB、イベント100,000個、hint2,000文字まで。曲長の固定上限はない。イベントは拍順に並べ直すので、編集時のファイル順は前後してもよい（同拍のhintの順序は維持）。

不正JSONでは現在の教材を保持し、イベント番号と項目を案内する。未知schemaVersionは読込不可。未知イベントは警告して無視し、練習はできるがその曲の自己ベストは保存しない。新しい機能を必要とする教材を古いアプリで正常対応した扱いにしない。

有料教材・非公開素材を公開リポジトリや公開サンプルへ混ぜない。認証・DRMはない。配布・共有の権利は教材制作者が確認する。
